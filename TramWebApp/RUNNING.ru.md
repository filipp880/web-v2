# Запуск TramWebApp

Проект находится в `D:\WebTRAMV\TramWebApp`. Основной проверяемый способ запуска — Docker Compose с PostgreSQL. Нужен работающий Docker Desktop с Linux-контейнерами.

## Запуск в PowerShell

```powershell
cd D:\WebTRAMV\TramWebApp
docker compose up --build -d
docker compose ps
```

При первом запуске скачиваются образы и зависимости. Дождитесь завершения команды. Таблицы создаются миграциями автоматически, затем добавляются демонстрационные пользователи, три прогона и телеметрия.

- Приложение: http://localhost
- Проверка API и PostgreSQL: http://localhost:8080/health — ответ `Healthy`.
- Состояние модели: http://localhost:8080/api/model/status
- pgAdmin: http://localhost:5050 — `admin@example.com` / `admin123`.
- PostgreSQL с компьютера: `localhost:5433`, база `tramwebapp`, пользователь и пароль `postgres`.
- PostgreSQL из pgAdmin: сервер `db`, порт `5432`, остальные параметры те же.

Для входа в приложение: `admin` / `admin123` или `operator` / `user123`. Откройте «Прогоны», выберите прогон, нажмите «Запустить модель». Стрелки и ползунок переключают точки телеметрии, воспроизведение перебирает их автоматически. Просмотр не записывает историю: нажмите «Сохранить результат» для выбранного шага. В «Корректировке оператора» можно сохранить исправленные скорость и пройденный путь, включая нулевые значения. Модель демонстрационная (`1.0.0-mock`).

Карта запускается **без API-ключа и без внешних запросов**. В сборку включены улицы, здания и трамвайные пути района Москвы; демонстрационные GPS-точки пересчитаны вдоль рельсов. Пунктир показывает заданный путь, точки — GPS, синяя линия — пройденную часть. При пропадании GPS положение оценивается по пройденному расстоянию вдоль заданной геометрии. Вне включённого района показывается схема пути; это не общероссийская подложка и не сервис поиска маршрутов. Геометрия хранится в `plannedRoute` прогона. Для реальных данных её нужно задавать по фактической трассе.

Источник геоданных и лицензия: [maps/README.md](frontend/public/maps/README.md). При обновлении приложение автоматически добавляет геометрию только трём исходным демопрогонам без маршрута, сохраняя пользователей и историю.

## Ручное управление и сценарии

### Непрерывное движение с автоматической записью в PostgreSQL

Откройте прогон с маршрутом → **«Управлять трамваем»**. Укажите начальную скорость и режим зимнего сцепления, нажмите **«Создать прогон»**, затем **«Продолжить движение»**. Будет создан отдельный прогон тренажёра, исходные записи не изменятся.

Ручка удерживает значение между шагами: +1 даёт тягу, 0 — выбег с сопротивлением движению, −1 — плавное торможение. Зимой ускорение и торможение ограничены сильнее. Изменение ручки не сбрасывает таймер и не обнуляет скорость. Можно поставить движение на паузу и записывать по одной секунде кнопкой «Шаг +1 с».

Каждый секундный шаг рассчитывает сервер и атомарно записывает телеметрию и результат в PostgreSQL. Пройденный путь сохраняется в колонке `tram_telemetry_points.distance_meters`. Таблица тренажёра показывает точки после чтения их из API, а не только локальные значения. Повтор того же шага не создаёт дубликат. При ошибке записи движение приостанавливается. После перезагрузки восстанавливаются скорость, путь и последняя записанная ручка; продолжение требует нажатия кнопки. Открыть сохраненные записи можно через ссылку под ручкой; страница телеметрии тренажёра обновляется каждые 3 секунды.

По умолчанию показана контрастная схема маршрута со стартом, финишем, значком трамвая и прогрессом. Кнопка «Карта» включает географическую подложку. При заданной геометрии расчетная позиция следует одному пути, GPS показан отдельными измерениями и не переключает маркер туда-обратно.

Динамика тренажёра учебная, с инерцией и ограничением ускорения; коэффициенты не калиброваны по реальному вагону. Она отделена от демонстрационной модели оценки скорости и редактора отдельных точек.

### Редактирование записанной телеметрии

В модели выберите шаг и используйте панель «Редактор записанных сигналов». Здесь изменяется одна точка записи, а не непрерывное движение. Ручка перемещается мышью, касанием или стрелками клавиатуры. Есть кнопки режимов и точный числовой ввод. Можно менять скорости передней/задней тележек и GPS (0–100 м/с); пустой GPS означает потерю сигнала.

После изменения модель автоматически пересчитывает сценарий; воспроизведение ставится на паузу. Правки каждого шага сохраняются при перемотке в пределах открытой страницы. Серый пунктир на графике скорости показывает исходную модель для сравнения. Пройденный путь пересчитывается с учётом предыдущих изменённых шагов, при отсутствии GPS карта использует этот путь. «Вернуть данные шага» отменяет изменения одной точки, «Сбросить все правки» восстанавливает исходный прогон.

«Сохранить результат» записывает изменённые входные значения и рассчитанные скорость/путь в историю. Сервер сам проверяет и пересчитывает сценарий перед сохранением. Исходная телеметрия в базе не изменяется. Несохранённые правки исчезают при перезагрузке страницы. Пока выполняется расчёт или введены неверные значения, сохранение заблокировано.

Это управление входами демонстрационной модели оценки скорости, а не физический симулятор разгона: если обе тележки показывают 0, одна ручка не создаёт движение.

## Остановка и повторный запуск

```powershell
cd D:\WebTRAMV\TramWebApp
docker compose stop
docker compose start
```

После изменения исходников снова выполните `docker compose up --build -d`. `docker compose down` удаляет контейнеры, сохраняя данные в Docker volume. Не добавляйте `-v`, если хотите сохранить базу.

## Проверки и журналы

```powershell
cd D:\WebTRAMV\TramWebApp
powershell -NoProfile -ExecutionPolicy Bypass -File .\smoke-test.ps1
docker compose logs --tail 100 api frontend
```

Сценарий проверяет авторизацию, роли, профиль, демонстрационные данные, CRUD прогонов, телеметрию, предсказания, метрики, историю и вмешательство. Он создаёт временный прогон и удаляет его после проверки.

Браузерные проверки (при запущенном Docker):

```powershell
cd D:\WebTRAMV\TramWebApp\frontend
npm ci
npx playwright install chromium
$env:TEST_BASE_URL = 'http://localhost'
npx playwright test
```

Проверяются вход, создание/редактирование/удаление временного прогона, поиск, все 200 шагов, пропуски GPS, пауза, сброс, сохранение и корректировка, пагинация, карта без внешних запросов, ширины 390–1440 px, ошибка API и пустая телеметрия, ручное управление, валидация и совпадение сохранённого сценария с предварительным расчётом. Проверки сохранения добавляют два результата в историю демопрогона.

## Разработка без Docker

Нужны SDK .NET 8 или новее, среда **ASP.NET Core Runtime 8** и Node.js 20 или новее. Для локальной разработки можно обойтись без PostgreSQL; данные в памяти исчезают при остановке backend.

Первое окно PowerShell:

```powershell
cd D:\WebTRAMV\TramWebApp
$env:ASPNETCORE_ENVIRONMENT = 'Development'
$env:StorageMode = 'InMemory'
dotnet run --project src/TramWebApp.Api --urls http://localhost:8080
```

Второе окно PowerShell:

```powershell
cd D:\WebTRAMV\TramWebApp\frontend
npm ci
npm run dev
```

Откройте http://localhost:5173. Swagger доступен в Development и при `Swagger__Enabled=true`: http://localhost:8080/swagger/index.html. В основном Docker Compose он включён, также доступен через http://localhost/swagger/index.html. Для проверки сборки: `dotnet build TramWebApp.sln` в каталоге проекта, `npm run build` и `npm run lint` в каталоге `frontend`.

Отдельный запуск ЛР2 в памяти, генерация тестовых данных и сопоставление требований: [LABS-COMPLIANCE.ru.md](LABS-COMPLIANCE.ru.md). Генератор: `powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\generate-test-data.ps1 -Runs 2 -Steps 25`.

Если порт PostgreSQL 5433 занят, задайте перед запуском Docker `$env:POSTGRES_PORT = '5434'`. Порты приложения 80, API 8080 и pgAdmin 5050 должны быть свободны.

Это конфигурация для локальной демонстрации. В зависимостях есть предупреждения аудита, а пароли и JWT-ключ демонстрационные; перед публичным размещением нужны отдельная настройка и обновление зависимостей.
